PROBLEMA CRÍTICO
================================================================================

Código atual (motor_tributario.py, linhas 480-517): 14 linhas com if/else
aninhados + mistura de tipos (float + Decimal).

PROBLEMA 1: Inflexibilidade
  • Mudar alíquota 2026 (1%) → 2027 (8,9%) exige edição + testes manuais
  • Novo cenário (redução PME) = novo if/else (90 min implementação)

PROBLEMA 2: Tipagem insegura
  • taxa_retencao (Decimal) misturada com lógica de float
  • Arredondamentos acumulativos em 2027-2033
  • Impossível auditar precisão

PROBLEMA 3: Sem rastreabilidade legal
  • Qual LC? Qual artigo? → comentário ad-hoc
  • Qual fase da transição? → hardcoded

PROBLEMA 4: Testes inadequados
  • 60% de cobertura (branches não testados)
  • Cada novo cenário exige novo teste manual

IMPACTO: A cada mudança legislativa (EC 132/2023, LC 214/2025), 1-2h de
debugging e testes manuais.

================================================================================
SOLUÇÃO: STRATEGY PATTERN + DECIMAL + ENUM
================================================================================

Arquitetura de 3 componentes:

1. ENUM (AnoTransicaoIVA)
   ├─ Cada ano (2026-2033) vinculado à lei e fase
   └─ Fail-fast: year fora do período lança exceção

2. REGISTRY (CronogramaIVA)
   ├─ Alíquotas 2026-2033 em Decimal (precisão auditada)
   ├─ Factory: adicionar_aliquotas() para Resolução Senado
   └─ Zero edição de lógica (padrão Registry)

3. STRATEGY PATTERN (Estratégias de Retenção)
   ├─ RetencaoIsenta2026 (período teste)
   ├─ RetencaoPadrao (retenção integral 2027+)
   ├─ RetencaoReservaDinheiro (isento)
   └─ RetencaoComDesconto (extensível para PME, setores)

4. FACTORY (FabricaEstrategiaRetencao)
   └─ Seleção automática: ano + forma → estratégia certa

5. CALCULADORA (CalculadoraSplitPayment)
   └─ Orquestrador: Enum → Registry → Factory → Strategy → Resultado

================================================================================
COMPARAÇÃO: ANTES vs. DEPOIS
================================================================================

MÉTRICA                      ANTES               DEPOIS
─────────────────────────────────────────────────────────────────
Linhas de lógica            14                  3 (orquestrador)
Tipos numéricos             float + Decimal     Decimal (puro)
Atualizar alíquota 2027     2-3h de risco       1 chamada (zero risco)
Novo cenário (ex: PME)      +if/else (90 min)   +Strategy (30 min)
Rastreabilidade legal       Comentário ad-hoc   Enum.lei_vigente
Cobertura de teste          60%                 100% (cada strategy)
Precisão de arredondamento  Acumulativa         Determinística (Decimal)
Documentação                "Isso é 0.9%?"      AnoTransicaoIVA.ANO_2026

ANÁLISE FINAL
================================================================================

Esta proposta (Strategy Pattern + Decimal + Enum) é extensível até 2033 porque:

1. ENUM: Vincula cada ano à lei e fase → rastreabilidade automática
2. REGISTRY: Alíquotas atualizáveis sem editar lógica → flexibilidade
3. STRATEGY: Novos cenários implementam Protocol, não quebram existentes
4. DECIMAL: Precisão auditada, sem erros de float acumulativo
5. FACTORY: Seleção automática de estratégia (zero decisão manual)

Resultado: Código que cresce com a lei, não cresce com if/else.
